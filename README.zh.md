# dsh-one-click-restart

给 DeepSeek Harness 用的**一键重启**插件：会话头部右上角一个刷新图标，加上一个系统级快捷键 —— 卡死时也能把应用重新拉起来，并自动接续被打断的工作。

| | |
|---|---|
| **解决什么** | DSH 卡死时点不动界面、也重启不了它，事后还不记得有哪些任务在跑 |
| **怎么解决** | ① 标题栏刷新图标　② 系统级热键（宿主卡死也能用）　③ 重启后自动接续 |
| **依赖** | **零**。只用 Windows 自带的 PowerShell 5.1 |
| **安装** | `dsh plugin --profile desktop add link:<本目录>` |
| **已验证** | 真机上完成过完整的"热键 → 关闭 → 重启 → 自动接续"闭环 |

> 本文档最后一个章节记录了开发中修掉的**六个真实缺陷**——每一个都属于"看起来正常、实际完全没工作"的类型。如果你要改这个插件，那一节比正文更值得读。

## 它解决什么问题

DSH 卡住时，你既点不动界面、也重启不了它，还得手动回忆刚才有哪些任务在跑。这个插件把这三件事一起解决：

- **点得动**：右上角工具区最右侧一个刷新图标（就在"打开侧边栏"按钮左边）。
- **点不动也能救**：系统级热键由**独立于 DSH 进程树的看门狗进程**监听，所以连主进程事件循环卡死时它照样生效。
- **不用回忆**：插件一直在后台记录"当前在跑什么"，重启后自动把中断的工作接上。

> 默认热键是 `Ctrl+Alt+R`。它在不少机器上已被别的软件占用（显卡驱动、壁纸引擎、输入法…），
> 插件会**检测冲突并列出当前真正可用的组合**，在设置页一键采用即可——它不会偷偷换键，
> 那只会让你按着一个没用的键。

## 安装

```bash
dsh plugin --profile <你的 profile> add dsh-one-click-restart
```

或者在本仓库目录下直接安装为本地链接：

```bash
dsh plugin --profile desktop add link:<本目录绝对路径>
```

装好后**重启一次 DSH**（host 端插件需要重启加载；客户端部分刷新页面即可）。

## 使用

| 操作 | 结果 |
|---|---|
| 点击右上角刷新图标 | 通过宿主要求看门狗重启 |
| 按 `Ctrl+Alt+R` | 看门狗直接重启（**不经过宿主**，卡死时仍然有效） |
| 设置 → 插件 → 一键重启 | 改键、恢复范围、熔断阈值、查看待恢复清单 |

重启过程是**先礼后兵**：先请求正常退出（让会话日志和任务账本落盘），等 3 秒（可调）后才强制结束，然后重新拉起应用。

## 快捷键冲突

如果提示"该组合键已被其它程序占用"（`Ctrl+Alt+R` 在不少机器上被 Wallpaper Engine、NVIDIA、输入法一类常驻软件占着），设置页会：

1. 明确告诉你冲突；
2. **列出当前真正可用的备选组合**（插件会逐个探测，探测时用完即还，不会抢占）；
3. 点一下即可采用，也可以直接按键录制自己的组合。

## 自动恢复

插件每隔几秒把"正在跑什么"原子写入 `~/.dsh/one-click-restart/pending.json`。**关键在于它是持续写入的，而不是在重启那一刻才写** —— 宿主要真卡死了，那一刻什么也写不出来。

重启后按快照逐项恢复：

| 类型 | 手段 | 可靠性 |
|---|---|---|
| 任务看板卡片 | `POST /api/task-board/action` 重新运行 | 高 |
| 目标（goal）会话 | 重新武装目标 | 高 |
| 后台任务 / 会话中被中断的一轮 | 记录并尽力接续 | 中 |

**熔断**：同一项连续失败达到阈值（默认 3 次）就放弃并记录，避免"一跑就崩的任务"把插件变成重启死循环。

## 设置项

- 快捷键（点击后按新组合即可改键）
- 看门狗开关、运行状态与进程号
- 是否只在 DSH 位于前台时响应快捷键（避免在别的软件里误触）
- 优雅关闭等待时长、熔断阈值
- 恢复范围（任务看板 / 目标 / 后台任务 / 会话）
- 重启后是否自动补一句「继续」

## 工作原理

```
① 客户端插件（页面内）  ── 刷新图标按钮 · 设置页 · tooltip
        │ 点击 → POST /api/one-click-restart/restart
        ▼
② Host 插件（dsh host 进程内）
        │ · 持续快照「在跑什么」
        │ · 拉起并监督看门狗
        │ · 重启后执行恢复 + 熔断
        ▼ spawn（detached，脱离进程树）
③ 看门狗（系统 PowerShell，隐藏窗口，独立进程）
          · RegisterHotKey 注册系统级热键
          · 前台窗口校验（只在 DSH 前台时响应）
          · 优雅关闭 → 强杀兜底 → 重新启动
```

**为什么必须三层**：看门狗不能是 host 的子进程（否则杀进程树时陪葬），也不能依赖 Electron 主进程（它卡死时 Electron 自己的 `globalShortcut` 也一并失效）。按钮和快捷键都指向同一个执行者，所以两条路径的行为永远一致。

## 零依赖

运行时不需要安装任何东西：

- 看门狗用的是 Windows 自带的 Windows PowerShell 5.1（不要求 PowerShell 7）；
- host 端只用 Node 内置模块；
- 客户端图标优先复用 DSH 自带图标，取不到时回退到内置 SVG。

## 数据与卸载

所有状态都在 `~/.dsh/one-click-restart/`：

| 文件 | 内容 |
|---|---|
| `settings.json` | 你的设置 |
| `pending.json` | 待恢复快照 |
| `history.json` | 历次恢复结果 |
| `watchdog.json` / `watchdog-state.json` | 看门狗的配置与自报状态 |
| `watchdog.log` / `watchdog-spawn.log` | 看门狗日志与启动诊断 |

卸载后删掉该目录即可。**注意**：卸载后如果看门狗进程仍在运行，先删目录再结束那个 `powershell.exe`；插件启动时会用停止哨兵让它自行退出。

## 已知限制与能力边界

如实说明当前边界，避免误期待。

### 已可靠工作

- **任务看板卡片**：重启后自动重新运行（走看板自己的 `/api/task-board/action`）。
- **带 goal 的会话**：重启后自动重新武装目标，由目标自己的轮次驱动器接着干。本插件开发过程中就是靠它连续三次自动续跑的。
- **看门狗本身**：脱离 DS 进程树、系统级热键、前台窗口校验、优雅关闭→强杀兜底、启动前等待与失败重试。

### 仅记录、不自动重放

- **后台任务（job）**：插件会把它记入"待恢复清单"并在设置页列出，但**不会替你自动重放**。

  依据不是偷懒：`jobs` 服务给出的 `JobView` 只有 `id / kind / label / status / progress / detail / startedAt / output` —— **没有任何字段携带原始命令**。重放所需的信息存在于 `JobSpec.run(job)`，那是一个函数，无法持久化。唯一可行的替代是解析会话日志文本，脆弱且容易出错，因此选择不实现，而不是实现一个会静默跑错命令的版本。

- 会话中被中断的那一轮不保证逐字续接上下文。

### 会话补继续（已实现，但默认建议关闭）

被硬中断的普通会话（没有 goal 的那种）现在能自动接续，判据是**引擎自己记录的事实**，不是猜测：

```
turn/start 有配对 turn/end   → 这一轮正常结束，会话只是空闲
turn/start 没有配对 turn/end → 进程在那一轮运行中被杀，确实被中断
```

插件反向扫描会话事件（只看尾部 2000 条），只在**最后一个 turn 未闭合**时才把该会话记入待恢复清单。

**但它默认建议保持关闭**，原因必须说清楚：恢复动作是往输入框写入「继续」并提交，而 **dsh 没有提供读取当前草稿的接口**（`InputActions` 只有 `setDraft` / `submit`）。也就是说，插件无法在动手前确认"输入框是不是空的"。尽管有三层降低风险的设计——判据准确、要求本次启动确有可恢复项、写入前延迟 5 秒——它**本质上仍然是在替你打字**。

需要这个能力时再打开；打开后请注意，重启之后的头几秒不要在输入框里打字。

### 其他

- 重启时窗口会消失 3~8 秒，这是 Electron 重载的物理限制；能保证的是**你不需要任何操作**。
- 若目标组合键被别的软件占用，插件**不会**偷偷换键（那会让你按着一个没用的键），只报告可用备选。
- 重启刚拉起应用时有一段启动窗口期，此时不会因为进程短暂不可见就误判"应用已退出"（已修）。

### 开发过程中修掉的六个真实缺陷

记录在此，因为它们都属于"看起来正常、实际不工作"的类型：

1. **`detached: true` 让看门狗静默死亡。** Windows 上它意味着 `DETACHED_PROCESS`，PowerShell 因此没有控制台，启动后立刻 exit 0 且不写任何东西。6 组对照实验证实：带该标志的全部失败，其余全部成功。改为两段式（启动器 + `Start-Process`）后解决。

2. **BOM 让状态文件"看起来不存在"。** 看门狗用 PowerShell 的 `Set-Content -Encoding UTF8` 写状态会带 3 字节 BOM，而宿主用 `JSON.parse` 读取会直接抛错——文件写得完全正确，宿主却认为它从没写过。读端剥离 BOM + 写端改用无 BOM 编码，双端修复。

3. **组件调用了 slot owner 并不提供的 `t`。** 会话头部工具区**不注入**翻译函数，而设置页与会话头部又是两个不同的 owner。调用一个不存在的 `t` 抛出 `TypeError`，被记录为 `slot entry crashed in 'conversation.session.header.utilities'`，并进一步导致 `Desktop renderer exited: crashed` —— 于是不只是图标不显示，**整个应用都起不来**。现在翻译器永远可调用：owner 给了就用，没给就回退到内置字典。

4. **`Start-Process` 在看门狗里创建不了任何进程。** 最后也是最隐蔽的一个：它**返回成功**（约 99 ms，无异常），但进程表里什么都不会出现——连看门狗自己的诊断观察者都起不来。看门狗是 dsh 宿主的后代，从这个位置无法创建子进程。日志因此一直呈现"`relaunched` 了、用户却还得手动打开"的假象。

   改为**用 WMI**（`Win32_Process.Create`）把创建动作交给 Windows 服务后，一次通过：

   ```
   23:00:26  started DeepSeek Harness via WMI (pid 198268)
   23:00:26  relaunch attempt 1
   23:00:34  relaunched DeepSeek Harness
   ```

真正定位它的，是一个**独立于看门狗的观察者进程**：一个停止写日志的进程无法解释自己为什么停，所以由外部每 200ms 采样"看门狗是否存活、应用有多少进程"。记录清楚地显示看门狗全程存活、应用进程数 `5→0→1→6`，一次成功：

```
23:00:18  watchdogAlive=True  appProcesses=5
23:00:23  watchdogAlive=True  appProcesses=0
23:00:26  watchdogAlive=True  appProcesses=1
23:00:40  watchdogAlive=True  appProcesses=6
```

这个观察者保留在 `watchdog/restart-observer.ps1`，每次重启都会自动运行，日志写在 `restart-trace.log`——下次再出问题时，它会先于任何猜测给出答案。

5. **设置页注册漏了 `label`，于是它"不存在"。** 列表型 slot 的 owner 会把 `label` 渲染成标签页的**可见文字**。只传 `locale` 而不传 `label`，会得到一个**存在但读不出来**的标签页——从用户视角看，和这个页面根本没注册完全一样。现在显式传入一个 thunk，跟随语言切换。

   > 另外补了一处体验问题：悬停提示原本写死「一键重启 (Ctrl+Alt+R)」。在你这台机器上这尤其误导——`Ctrl+Alt+R` 被别的软件占用，写死的提示会一直让人去按一个没用的键。现在提示会读取**当前实际生效**的组合，并在每次鼠标悬停时刷新，改键后无需刷新页面即可看到。

6. **"自动补继续"曾经每次加载都抢用户的输入框。** 这是我自己引入的、也是使用体验上最严重的一个：`probeSessions` 把**每一个活跃会话**都写成待恢复项，于是快照永远非空、启动时的"确有可恢复项"判据永远为真 —— 结果是**每次页面加载**，插件都会 `setDraft('继续')` + `submit()`，覆盖用户正在输入的草稿，并替他发出一条消息。

   修复分两步，缺一不可：

   - **换判据**：不再问"会话是否活着"（每个打开的会话都满足），而是问**"最后一个 turn 是否闭合"** —— 反向扫描引擎自己的 `turn/start` / `turn/end` 事件，未闭合才是真被中断；
   - **加保护**：`resumedFromSnapshot` + 逐宿主标记 + 写入前延迟 5 秒。

   > 教训：这个功能我改坏了三版，前两版都在**没有可靠判据**的情况下强行实现。正确做法是先找到引擎里那份能回答问题的数据，再动手。
